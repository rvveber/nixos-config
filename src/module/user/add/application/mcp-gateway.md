# Shared MCP gateway

`services.mcpGateway` runs one Docker MCP Gateway for all harnesses of a login
user. The user scope is intentional: profiles, credentials, the Docker socket,
and harness configuration share the same identity.

The stable client contract is:

- Streamable HTTP: `http://127.0.0.1:8811/mcp`
- Health check: `http://127.0.0.1:8811/health`
- Authentication: `Authorization: Bearer <token>`
- Token file: `~/.local/state/mcp-gateway/auth-token`, mode `0600`

The module fixes the listener to loopback, requires bearer authentication,
enforces declared network allowlists, enables secret scanning, call logging,
and image-signature verification, and defaults every server container to one
CPU and `2Gb` of memory. Extra host paths can only be added as read-only roots
through `services.mcpGateway.readOnlyBindPaths`.

## Apply and operate

The user configuration enables the service on hosts with Docker. Currently
that means `b1kini`; `cake` keeps the module disabled.

```console
sudo nixos-rebuild switch --flake ./src#b1kini
systemctl --user status mcp-gateway
curl --fail http://127.0.0.1:8811/health
journalctl --user --unit mcp-gateway --follow
```

The first service start creates the authentication token. Load it into a shell
for clients that support environment-backed bearer tokens:

```console
export MCP_GATEWAY_AUTH_TOKEN="$(cat "$HOME/.local/state/mcp-gateway/auth-token")"
```

Desktop applications only inherit this variable when their process environment
contains it. Prefer the client's secret store when it offers one.

## Profiles and catalogs

The gateway starts successfully with an empty `default` profile. Create and
populate it through the installed Docker CLI plugin:

```console
docker mcp profile create --name Default --id default
docker mcp profile server add default --server catalog://mcp/docker-mcp-catalog/SERVER_NAME
docker mcp profile tools default --enable SERVER_NAME.TOOL_NAME
docker mcp profile show default
systemctl --user restart mcp-gateway
```

Local catalog and server definitions belong below
`~/.docker/mcp/catalogs/` and can be added with a catalog-root-relative URI such
as `file://servers/example.yaml`. Pin Docker MCP images by digest. Keep the tool
allowlist narrow, declare `allowHosts` for networked containers, use
`disableNetwork: true` for offline containers, and restart the service after
profile changes.

`docker mcp client connect` is deliberately outside this configuration. Each
harness remains user-owned and connects manually to the stable endpoint.

## Connect a harness

Every harness needs the endpoint above and the bearer token. The following are
client-side examples; none are generated by Nix.

### Codex

Add this to `~/.codex/config.toml` and start Codex with
`MCP_GATEWAY_AUTH_TOKEN` in its environment:

```toml
[mcp_servers.docker_gateway]
url = "http://127.0.0.1:8811/mcp"
bearer_token_env_var = "MCP_GATEWAY_AUTH_TOKEN"
```

Codex CLI, IDE, and desktop share this configuration. See the
[Codex MCP documentation](https://developers.openai.com/codex/mcp).

### Claude Code

Claude Code accepts HTTP servers at user or project scope. In a project
`.mcp.json`, it expands environment variables in header values:

```json
{
  "mcpServers": {
    "docker-gateway": {
      "type": "http",
      "url": "http://127.0.0.1:8811/mcp",
      "headers": {
        "Authorization": "Bearer ${MCP_GATEWAY_AUTH_TOKEN}"
      }
    }
  }
}
```

See the [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp).

### VS Code

Run `MCP: Open User Configuration` and use a password input so the token enters
VS Code's secret storage instead of the JSON file:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "mcp-gateway-token",
      "description": "Local MCP gateway token",
      "password": true
    }
  ],
  "servers": {
    "docker-gateway": {
      "type": "http",
      "url": "http://127.0.0.1:8811/mcp",
      "headers": {
        "Authorization": "Bearer ${input:mcp-gateway-token}"
      }
    }
  }
}
```

See the [VS Code MCP configuration reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

### OpenCode

OpenCode supports environment references in remote headers. Add this to the
user `opencode.json` and start OpenCode with `MCP_GATEWAY_AUTH_TOKEN` in its
environment:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "docker-gateway": {
      "type": "remote",
      "url": "http://127.0.0.1:8811/mcp",
      "enabled": true,
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:MCP_GATEWAY_AUTH_TOKEN}"
      }
    }
  }
}
```

See the [OpenCode MCP documentation](https://opencode.ai/docs/mcp-servers/).

### Cursor and Gemini CLI

These clients use the same URL and header with different outer schemas:

| Harness | User configuration | Server shape |
| --- | --- | --- |
| Cursor | `~/.cursor/mcp.json` | `mcpServers.<name>.url` and `.headers` |
| Gemini CLI | `~/.gemini/settings.json` | `mcpServers.<name>.httpUrl` and `.headers` |

Use `Authorization: Bearer TOKEN_FROM_AUTH_FILE` in the `headers` object,
replacing the placeholder only in the untracked per-user file. Restrict a file
containing the expanded token to mode `0600`. Refer to the current
[Cursor](https://prod.cursor.com/help/customization/mcp),
[Gemini CLI](https://geminicli.com/docs/tools/mcp-server/) documentation before
adapting the surrounding schema.

## Secret boundary

The gateway authentication token only protects the local HTTP endpoint. Server
credentials are a separate concern.

Docker MCP's current community secret and OAuth flows depend on the experimental
Docker Secrets Engine and `docker pass`. This NixOS configuration provides
Docker Engine rather than Docker Desktop and does not yet package that backend.
Profiles without server credentials work now. Add a separately reviewed Secrets
Engine module before enabling credential-dependent servers; plaintext `.env`
files are not the fallback.

Upstream currently marks Docker MCP Gateway releases as pre-releases. The
package is pinned, hash-verified, and should be upgraded only after reviewing
release security changes and rebuilding the activation package.
